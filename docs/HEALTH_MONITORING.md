# :hospital: 健康監控與自動化運維

## :clipboard: 功能概述

本次實作新增了兩個核心模組，並實現精準時間調度系統：

### :clock2: **精準時間調度系統** :new:
- **匯率檢查**: 每小時整點和30分精確執行 (10:00, 10:30, 11:00...)
- **健康檢查**: 每小時15分和45分精確執行 (10:15, 10:45, 11:15...)
- **任務生命週期管理**: 全域任務追蹤，支援優雅取消和重啟
- **時間同步**: 每日維護時重新調度任務，防止長期時間漂移

### :hospital: **健康監控系統** (`SystemHealthMonitor`)
- **全面健康檢查**：API狀態、系統資源、數據完整性、文件系統、服務狀態
- **快速健康檢查**：輕量級檢查，適合頻繁執行
- **簡化健康歷史**：記錄最新檢查狀態和問題歷史 :new:
- **智慧警報**：自動檢測異常並記錄
- **精準調度**: 15分和45分自動執行 :new:

### :wrench: **自動化運維** (`AutoMaintenance`)
- **每日維護任務**：日誌清理、備份管理、數據優化、性能檢查、健康歷史清理 :new:
- **緊急清理**：磁碟空間不足時的快速清理
- **自動重啟**：關鍵故障時的自動恢復
- **運維記錄**：維護活動的完整日誌

## :rocket: **新增指令**

### `/system [detailed=False]`
**整合系統狀態檢查**
- `detailed=False`: 快速狀態檢查（整體狀態、運行時間、記憶體使用、健康指示）
- `detailed=True`: 詳細系統報告（健康檢查、系統資源、建議、維護狀態）

**使用範例：**
```
/system                    # 快速系統狀態
/system detailed:True      # 詳細系統報告
```

### `/health [quick=False]`
**系統健康檢查**
- `quick=True`: 快速檢查（API、記憶體、數據文件）
- `quick=False`: 全面檢查（所有項目詳細分析）

**使用範例：**
```
/health quick:True     # 快速健康檢查
/health                # 全面健康檢查
```

### `/maintenance [operation="summary"]`
**系統維護管理**
- `operation="summary"`: 查看維護活動摘要
- `operation="daily"`: 執行每日維護任務
- `operation="emergency"`: 緊急清理（釋放磁碟空間）

**使用範例：**
```
/maintenance                      # 維護摘要（預設）
/maintenance operation:daily      # 執行每日維護
/maintenance operation:emergency  # 緊急清理
```

## :alarm_clock: 自動任務

### 1. **健康監控任務** - 每15分鐘
- 執行快速健康檢查
- 記錄系統狀態變化
- 檢測連續失敗並觸發自動重啟

### 2. **每日運維任務** - 每24小時（凌晨2點）
- 清理舊日誌文件（保留30天）
- 智慧備份清理（7天內全保留，超過7天保留週一備份）
- 數據庫優化和壓縮
- 系統性能檢查和記憶體清理
- 健康檢查問題歷史清理（7天） :new:
- 磁碟空間檢查

## :dart: **監控指標**

### **API健康度**
- 玉山銀行API回應時間和狀態
- 備用API可用性
- 連續失敗次數追蹤

### **系統資源**
- 記憶體使用率（警告閾值85%）
- 磁碟使用率（警告閾值90%）
- CPU使用率監控
- 網路連接狀態

### **數據完整性**
- 主數據文件狀態和更新時間
- 備份文件數量和完整性
- 匯率歷史記錄檢查
- JSON格式驗證

### **服務狀態**
- 程序運行時間
- 記憶體使用和洩漏檢測
- 程序執行緒和文件句柄

## :card_file_box: **健康檢查資料結構** :new:

### **簡化的儲存格式**
```json
{
  "health_check_history": {
    "last_quick_check": {        // 最新快速檢查
      "timestamp": "2025-07-29T17:15",  // 分鐘級精度
      "status": "healthy"        // healthy/warning/critical
    },
    "last_detailed_check": {     // 最新詳細檢查
      "timestamp": "2025-07-29T17:06",
      "status": "healthy"
    },
    "problem_history": [         // 問題記錄陣列
      {
        "timestamp": "2025-07-22T14:30",
        "check_type": "quick",
        "status": "warning",
        "warnings": ["API回應時間過長"],
        "errors": []
      }
    ]
  }
}
```

### **資料清理政策**
- **last_quick_check**: 永不自動清除，只會被新檢查覆蓋
- **last_detailed_check**: 永不自動清除，只會被新檢查覆蓋  
- **problem_history**: 每日凌晨2:00維護時清理超過7天的記錄

## :hammer_and_wrench: **維護策略**

### **日誌管理**
- 自動清理30天以上的日誌
- 大型日誌文件自動輪轉
- 支援日誌壓縮以節省空間

### **健康歷史管理** :new:
- 問題記錄保留7天（每日維護清理）
- 最新檢查狀態永久保留
- 分鐘級時間戳精度，節省存儲空間

### **備份清理**
```
時間範圍          保留策略
0-7天            全部保留
8-28天           僅保留週一備份
29-90天          僅保留月初備份
90天以上          自動刪除
```

### **性能優化**
- 記憶體使用超過300MB時自動清理
- 健康檢查歷史自動截斷
- 垃圾回收和記憶體最佳化

### **自動恢復**
- 連續失敗5次自動重啟
- 重啟前等待60秒延遲
- 使用外部腳本確保重啟成功

## :bar_chart: **配置選項**

可在 `auto_maintenance.py` 中調整的配置：

```python
self.config = {
    'log_cleanup': {
        'retention_days': 30,        # 日誌保留天數
        'max_file_size_mb': 100,     # 日誌文件大小上限
        'compress_old_logs': True    # 是否壓縮舊日誌
    },
    'backup_cleanup': {
        'retention_days': 7,         # 完整保留天數
        'weekly_retention_weeks': 4, # 週備份保留週數
        'monthly_retention_months': 3 # 月備份保留月數
    },
    'auto_restart': {
        'max_consecutive_failures': 5, # 觸發重啟的失敗次數
        'restart_delay_seconds': 60,   # 重啟前等待時間
    }
}
```

## :mag: **監控閾值**

可在 `health_monitor.py` 中調整的閾值：

```python
self.thresholds = {
    'memory_usage_percent': 85.0,     # 記憶體警告閾值
    'disk_usage_percent': 90.0,       # 磁碟警告閾值
    'api_response_time_ms': 5000,     # API回應時間警告閾值
    'consecutive_api_failures': 3,    # API連續失敗警告閾值
    'data_file_age_hours': 24,        # 數據文件過舊警告閾值
}
```

## :bulb: **使用建議**

### **日常操作**
1. **每週檢查**：`/health` 查看系統整體狀況
2. **定期維護**：`/maintenance operation:daily` 手動執行維護
3. **問題排除**：`/maintenance operation:summary` 查看維護歷史

### **緊急情況**
1. **磁碟空間不足**：`/maintenance operation:emergency`
2. **系統異常**：`/health` 診斷問題
3. **API故障**：`/system` 檢查API狀態

### **效能優化**
- 系統會自動在凌晨2點執行維護，避開使用高峰
- 健康檢查每15分鐘執行，及時發現問題
- 記憶體和磁碟使用會自動監控和清理

## :rotating_light: **警報機制**

系統會在以下情況自動記錄警告：
- 記憶體使用率 > 85%
- 磁碟使用率 > 90%
- API回應時間 > 5秒
- 連續API失敗 ≥ 3次
- 數據文件超過24小時未更新

系統會在以下情況觸發自動重啟：
- 連續健康檢查失敗 ≥ 5次
- 關鍵API完全無法訪問
- 系統資源嚴重不足
